# Native Git workflows

`Cmd-G` opens this native mod. It targets [Lazygit's feature guide](https://github.com/jesseduffield/lazygit#features) and [keybinding reference](https://github.com/jesseduffield/lazygit/blob/master/docs/keybindings/Keybindings_en.md), while keeping Herdr's graph, Markdown/Mermaid previews, Writer and Vim motions. `L` or **More → Open Lazygit** opens the installed upstream program on the same repository and machine; quit it to return to the native view. The target is native 1:1 workflow parity; it is not reached yet (see **Status** below). The evidence and remaining gaps below distinguish verified behavior from work still in progress.

## Status (stabilized 2026-11-16)

This spec is frozen at the current build while the parity route is planned. Planning lives in the wayfinder map, [GitHub issue #2](https://github.com/raphaelmans/herdr-app/issues/2), which is paused. The tables below describe what exists; the audits on that map measured it against Lazygit's pinned source:

- **Keybindings:** of 115 list-panel bindings, 69 match, 31 deviate and 15 are missing. Of about 150 commit, global, main-panel and menu bindings, about 55 match, 50 deviate and 45 are missing. Details: [list panels](https://github.com/raphaelmans/herdr-app/blob/research/keybindings-list-panels/research/keybindings-list-panels.md), [commits and global](https://github.com/raphaelmans/herdr-app/blob/research/keybindings-commits-global/research/keybindings-commits-global.md).
- **Configuration:** every pinned key is read; about 35 settings and about 133 of 170 keybinding names affect behaviour. No legacy-key migrations are applied. [Details](https://github.com/raphaelmans/herdr-app/blob/research/config-coverage/research/config-coverage.md).
- **Deliberate or undecided deviations** (open decisions on the map): commit rewrites (`s` `f` `d` `e` `r`) open a reviewed rebase plan instead of acting at once; `i` starts from the selected commit (Lazygit's `e` semantics); several Lazygit menus are a single prompt here (`r` rebase, `w` new worktree, Worktrees `d`, branch `u`, Files `D` and `S`); about 17 keys mean something else natively; native adds confirmations Lazygit lacks (Space checkout, every `g` mode, CommitFiles `c`).

### Known bugs

- A submodule at `MM` cannot be unstaged: Space and `a` stage it again every time. A submodule with only changes inside it stages silently with no effect; Lazygit reports "Nothing to stage".
- Nested repositories (`dir/` entries with their own `.git`) can be staged, and their preview fails; Lazygit refuses both. Discard asks one generic question for every `dir/`, plain folders included.
- Stash and reset on a submodule leaves its new commit checked out.
- Ctrl-O in Commit files copies `undefined`. Elsewhere Ctrl-O copies a full commit hash where Lazygit copies 12 characters, and it does nothing outside commits.
- The `?` help table says `D` discards all changes; `D` opens the reset menu. It also omits several keys that exist (Files `c` `C` `r` `S`; Stash `n` `r` `w` `enter`).

Research on [submodules and nested repositories](https://github.com/raphaelmans/herdr-app/blob/research/submodules-nested-repos/research/submodules-nested-repos.md) holds the design inputs for the first three.

`?` shows keys (its table is incomplete; see Known bugs). `m`, Actions buttons and right-click expose operations without memorizing keys. `g` opens reset choices on branch and commit lists (not yet in Files, where Lazygit's `g` opens upstream reset options); `<`/`>` and Home/End move to list ends. Stash uses `g` for pop. The native Git mod makes this contextual exception to the usual Vim motions for upstream parity. The graph keeps its previous quick keys; its menu includes the commit operations. Reflog and branch-history contexts cannot rewrite commits, including through custom patches. `y` opens the commit attribute menu; Ctrl-O copies the full hash (commits only). `v` or Shift-arrow selects commit ranges; `C` copies them and Ctrl-R clears the copied set. Commit search keeps surrounding history; reflog filtering narrows its rows. Menus accept item keys and `/` filtering and retain explanations for unavailable actions. Escape leaves a text field first, retaining its draft, then steps out of the component.

The tab groups follow [Lazygit's default side panels](https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md): Files / Worktrees / Submodules, Local branches / Remotes / Tags, and Commits / Reflog. Remote branches are a child of one remote, as in [Lazygit's remote controller](https://github.com/jesseduffield/lazygit/blob/master/pkg/gui/controllers/remotes_controller.go), and never a sibling tab. Filtering a remote's branches cannot expose another remote's branches.

Files Space acts on selected visible rows and their directory descendants, deduplicating overlapping children. It stages unstaged changes when any are selected, otherwise unstages the selection. `a` determines stage/unstage from the displayed tree: a text filter limits the operation to displayed paths; otherwise stage-all runs `git add -A`, or `git add -u` for the tracked filter, and unstage-all resets the whole index. Git ignore rules still apply. The discard menu has All (`x`, configurable) and Unstaged (`u`); Unstaged requires both staged and unstaged changes in the selected scope. Cancelling the menu retains the range; starting discard clears it, including on failure. Discard may have partial effects if a Git command fails.

Ignore/Exclude (`i`) accepts one row. Tracked files require confirmation before removal from the index; their worktree contents remain. Patterns escape literal glob characters. The copy menu (`y`) disables name/path/selected-diff actions for multiple rows but allows the repository's full staged diff, or full unstaged diff when nothing is staged. CommitFiles also offers historical file contents. Neither copy menu silently copies only the last row of a range.

Branch deletion (`d`) offers Local (`c`), Remote (`r`) and Both (`b`). Remote deletion follows each selected branch's own upstream; Both deletes upstreams before local branches. Current branches and missing upstreams show the relevant disabled choices. Local deletion checks whether commits are merged into HEAD, upstreams or configured main branches before asking about unmerged commits. A branch checked out in another worktree offers removal or detachment; a range containing one is refused. Worktree removal from this flow asks for force only after Git refuses the ordinary removal; the Worktrees panel's own `d` does not retry.

Fast-forward (`f`) fetches selected upstreams, checks every branch before moving any local ref, then batches unchecked-out refs and updates checked-out worktrees. Rewritten upstreams are accepted only when their reflogs account for every discarded commit; reset worktrees must have clean tracked files. Rebase/bisect worktrees and ahead-only branches are refused. A failed worktree update does not prevent the remaining checked-out branches from being attempted. The range remains selected. A local upstream (`remote = .`) is read directly instead of attempting the upstream source's invalid `refs/remotes/./` destination.

Tags `d` offers the same Local/Remote/Both choices. Remote deletion and `P` push always open a remote field prefilled with `origin`. Local tag deletion needs no second confirmation and collapses its range after refresh, including a partial command failure. Stash `d` confirms the captured range and drops highest stash indices first, checking identities before mutation. Successful branch/stash deletion collapses the range only when refreshed rows arrive. Operations that may have partially changed refs refresh even on failure; this intentionally avoids stale lists in upstream failure paths. Git Graph's stash Space action uses the same captured-identity check as its menu Apply action.

Commit ranges show one combined diff from the bottom selected commit's parent to the top selected commit. Enter opens that diff's files in the same pane, retaining the parent range; an initial commit uses the empty tree. Files added then removed within the range disappear from the combined result. Rename rows retain both paths for previews and custom patches. Combined or nested histories cannot rewrite a single commit. TODO endpoints and mixed-divergence nested endpoints fall back to the moving commit, following upstream.

## Graph details and reference badges

The graph keeps its primary commit and optional comparison separate from side-pane selection. Comparison direction follows displayed row order. Details appear immediately below the primary row, with graph lanes continuing through the space: full metadata and commit message on the left, changed files on the right. Root commits use an empty tree; merge commits compare against their first parent. A single stash includes its saved untracked files, while comparisons use the selected commit trees. Uncommitted changes respect Git ignore rules and include non-ignored untracked files.

The changed-files pane offers a compact directory tree or a flat list in the same directory-first order. A text file opens a native patch preview; Escape restores the graph and details. Renames retain both literal paths, including tabs, newlines and Unicode. Binary entries have no diff action when Git supplies no line counts. File view is remembered per repository and machine. The current preview temporarily replaces the graph; matching Git Graph's separate editor while keeping the graph visible remains open work.

Local branches and matching remotes share a badge but retain separate click targets. Remote names containing slashes are resolved from configured remotes. Local/remote/tag/stash menus act on the clicked reference, even when another side-pane item is selected. They include branch rename/delete/push, remote fetch/pull/checkout, annotated tag details and local/remote tag deletion, and stash apply/pop/drop/branch. A new branch from a remote respects Git's `branch.autoSetupMerge` setting. Local deletion offers force and optional matching remotes; stash apply/pop offer index restoration. Graph's stash-branch action runs `git stash branch`, preserving its distinct restore-and-drop behavior.

Remote checkout always asks for a local name. An existing name offers another name or checkout of that exact branch followed by a pull from the clicked remote. An unknown remote keeps the full suggested name and offers checkout without pull. Local and remote reference identities are checked before the operation. Branch, tag and remote labels are derived from their full namespaces, so a branch and tag sharing a name do not acquire Git's ambiguous short-name prefixes.

The commit row's menu is distinct from its reference badges. Checkout always confirms a detached checkout at that exact hash, even if branches point to it. Cherry-pick offers Record origin and No commit; merge cherry-pick and revert offer a one-based parent selector, defaulting to the first parent. Graph shortcuts Space, `c`, `t`, `r`, `b` and `y` reach these Graph actions, reset, branch creation and direct hash copy. New branches default to keeping the current checkout; new tags default to annotated, with a separate lightweight choice. Reset offers soft, mixed and hard modes with explicit confirmation.

Creating a branch or tag with an existing name offers explicit replacement or another name, retaining editable checkout, tag type, message and push choices. Replacement rechecks the existing reference, including an annotated tag's object identity; Git still refuses replacing a checked-out branch. A single remote uses an unchecked push checkbox; multiple remotes use a selector defaulting to no push. A failed push keeps the newly created local tag and refreshes the lists.

The uncommitted row has its own stash, reset, clean and Files actions. Stash accepts an optional message and defaults to including untracked files. Reset offers mixed or hard, defaulting to mixed, and confirms the effect. Clean confirms deletion and defaults to including untracked directories; ignored files and nested repositories are kept. These actions capture HEAD and the current branch before their forms and recheck both before mutation.

Drop appears only for a non-root commit on a loaded, non-branching descendant chain reaching HEAD, with no merges along that chain. It confirms the captured commit, checks HEAD and the current branch, then rechecks the actual replay range for merges before rebasing. Later linear commits are replayed. This extra Git check refuses a merge omitted by incomplete graph data.

Mutations recheck captured reference identities. Merge, rebase, pull, stash apply/pop, cherry-pick, revert, reset and drop also recheck both HEAD and the checked-out branch after options or confirmation, including a switch between branches at the same commit. Old detail controls cannot change a replacement selection. Forms and confirmations block background pointer events, and Graph actions ignore background badge events while a form, confirmation or menu is active. These menus still have the option and configuration gaps listed below.

## Configuration and custom commands

The native mod reads Lazygit's global and repository configuration on the repository's machine, including `CONFIG_DIR`, `LG_CONFIG_FILE`, XDG paths, main-worktree ancestors and the common Git directory. More → Lazygit configuration lists the sources and parse errors. Invalid reloads keep the last valid settings. Repository-root `.lazygit.yml` is excluded as upstream does; a repository override belongs in its common Git directory. Configuration is never written by this mod.

Supported settings include tree/filter/sort behavior, side-panel width, footer visibility, diff context/whitespace/rename threshold, log ordering, refresh/fetch intervals, auto-stage resolved conflicts, stash warnings and destination, sign-off, force-push restrictions, hosting services, merge arguments/messages/manual continuation, keybindings and custom commands. Git-flow and manual merge continuation follow `promptToReturnFromSubprocess`; failures always wait for acknowledgment. Zero or negative refresh intervals disable their background jobs. The default substring filter uses upstream smart case and whitespace terms; fuzzy filtering uses its stable ranking. Commit search searches literal text while retaining surrounding history.

`git.merging.args` uses Lazygit's whitespace splitting and flag precedence. `squashMergeMessage` substitutes plain or dotted `selectedRef` and `currentBranch` placeholders literally, including multiline messages. `manualCommit` opens Git's configured editor when continuing a merge or squash merge; initial regular merges and immediate squash-and-commit skip the editor. Leaving a squash uncommitted suppresses the automatic continuation prompt after conflict resolution; explicit Continue remains available.

Configured commands capture their repository and selected objects before prompting. Input, confirmation, menu and command-output menus support named form values, indexed responses, conditions, groups, shortcuts and input suggestions. Go-style templates support quote/runCommand and supported built-ins. Output can be silent, a popup, a live log or a terminal/PTY. Preparation and execution show loading status; cancelling a prompt prevents execution. Unsupported template or RE2 filter syntax reports an error instead of silently changing its meaning. Output and metadata reads are bounded before entering the native script.

Keybindings resolve contextual commands before global commands. Remapped or disabled default keys cannot fall through to their former actions. Text input retains ordinary typing. Some upstream bindings and display settings still depend on workflows listed below; this is not complete YAML behavior parity.

## What still uses upstream Lazygit

`L` provides the actual installed Lazygit, including external diff renderers. Its features follow the installed version (0.55.1 at implementation time), not a vendored snapshot. New native rebase plans, author-range edits, commit-file discard and custom-patch history rewrites reject ranges containing merge commits; use upstream for those histories. Native PR URLs support the upstream hosting mappings and services overrides; looking up an existing GitHub PR uses the optional `gh` CLI.

Native undo/redo reads up to 1,001 HEAD reflog entries, using Lazygit's action and marker rules for commits/amends, resets, pulls, checkouts and completed rebases. Existing Lazygit undo/redo markers are recognized, and native recovery writes compatible markers. Commit undo uses a soft reset, keeping the undone changes staged. Rebase undo and commit/rebase redo use a hard reset with an auto-stash for tracked local changes. Checkout first keeps compatible edits and offers auto-stash if they prevent switching. A failed reapply keeps the snapshot in Stash.

Recovery confirms the exact destination, then checks that HEAD, the checked-out branch, reflog and destination still match. Active operations, missing/initial commit targets, incomplete reads and obstructing untracked or ignored files are refused. It does not undo arbitrary working-file edits, stash changes or branch deletion. Action recognition follows upstream's parser; it is not a generic reversal of every reflog message.

## Data and mutation boundaries

- Actions are anchored to the repository and machine captured when the dialog opens. Entering a worktree/submodule changes that anchor explicitly.
- Git arguments are arrays. Patch bytes enter a fixed shell script as an argument, never executable shell text. Custom commands entered with `:` intentionally run as shell code.
- Configured custom commands intentionally run user-supplied shell code only when invoked. Prompt values passed through `quote` are quoted for the command's captured shell. Merely loading configuration does not run commands.
- Partial changes retain the original diff bytes, compare the current diff before applying, and run `git apply --check`. Display truncation and expanded tabs never become patches.
- Reads are reduced outside the mod's script heap. Files show up to 2,000 entries; local/remote refs are bounded to 1,000 per query; Git Graph, local commits and reflog start at 300 and extend by 100; stashes remain bounded to 300. Graph ordering happens in Git before the page limit, and the all-branches graph includes stash-only base commits. Wide graphs scroll horizontally. Searches cover loaded history.
- Partial patch reads are capped at 256 KiB and 4,000 display lines. Whole-file custom patches retain raw bytes without per-line objects, capped at 1 MB per file and 8 MB total. Larger patches report the limit. Rebase plans are capped at 500 commits; merge-containing ranges are rejected before rewriting.
- Destructive actions and history rewrites require a concrete confirmation in the mod. Commit submission never silently stages the working tree. Rebase conflicts leave Git's operation state available for continue/abort.
- Recovery snapshots use a private Git ref while running; successful cleanup compares its object ID before deleting it. No numbered stash entry is deleted. Failures publish the snapshot in Stash; if that also fails, the error identifies the retained `refs/herdr/recovery/…` ref.
- Git-flow Finish confirms the captured branch and checks its tip and prefix mapping immediately before launching. Legacy prefixes take precedence over git-flow-next. The external command decides integration, hooks, tags and branch retention. Its terminal stays available if observation or output capture fails, or the parent dialog closes before completion; cleanup errors do not change the recorded command result. **Open terminal** remains available while the action is running, including when the normal footer is hidden.
- Merge confirmations capture the selected ref, current HEAD/branch and settings, then recheck them before execution. Squash rechecks staged changes and writes its message only if Git created SQUASH_MSG, using the worktree-specific Git directory. Manual continuation uses the same recoverable terminal lifecycle as Git-flow.
- Tests use disposable repositories and a local bare remote. They do not operate on the user's working repository.

## Waiting

Every wait shows where its result will land, with one spinner that turns natively:

| --- | --- |

| Branch/tag/stash ranges | Branch deletion preparation shows "Reading branch deletion options" and "Checking selected branches"; mutations, fast-forward and their final refresh retain a labeled footer spinner |

An action pressed before the repository is read says so. A read that was overtaken (the selection moved on, another repository was entered, the dialog closed) is dropped and leaves no spinner.

## Validation

```sh
node --experimental-vm-modules --test mods/git/*.test.js
herdr-app check mods/git
herdr-app check mods/lazygit
herdr-app status | jq .errors
```

`status.test.js` covers ignored paths, untracked settings, NUL renames and actual operation states; `history.test.js` covers skewed commit dates, stash-only ancestry and page boundaries. `graph.test.js` checks wide graph geometry. `patch.test.js` applies real patches with Git. `workflows.test.js` exercises native event handlers against real temporary repositories with a mocked Herdr host. `render.test.js` runs the real Herdr checker with populated diff, menu, commit form, branch, worktree, submodule, reflog, rebase, conflict, help and every waiting state.
